SO, sistema de arquivos

Windows x Linux, comandos de navegação no shell e o Windows Explorer.

01 · CONCEITOSWindows e Linux organizam arquivos de formas diferentes+

Um sistema de arquivos é a forma como o sistema operacional organiza, nomeia e localiza os dados guardados no disco. Windows e Linux resolvem isso de maneiras parecidas na ideia — pastas dentro de pastas — mas diferentes em vários detalhes práticos.

  • Formato do disco. O Windows usa NTFS como padrão (e FAT32/exFAT em pendrives e cartões); o Linux usa mais comumente ext4, entre outros formatos (btrfs, xfs).
  • Raiz da árvore de pastas. No Windows, cada disco tem sua própria letra e sua própria raiz (C:\, D:\...). No Linux existe uma única raiz (/) para tudo; outros discos e dispositivos são "montados" dentro dela, em pontos como /mnt ou /media.
  • Separador de caminho. Windows usa contrabarra: C:\Usuarios\Fernando. Linux usa barra: /home/fernando.
  • Maiúsculas e minúsculas. O Windows é case insensitive: Documento.txt e documento.txt são o mesmo arquivo. O Linux é case-sensitive: são dois arquivos diferentes.
  • Permissões. O Linux exibe permissões de leitura, escrita e execução por usuário/grupo/outros diretamente no terminal (algo como -rwxr-xr-x). O Windows também tem permissões (ACLs), mas geralmente são configuradas pela interface gráfica, nas propriedades do arquivo.

Árvore de diretórios no Windows

C:\
├── Windows\              → arquivos do sistema operacional
├── Program Files\        → programas instalados (64 bits)
├── Program Files (x86)\  → programas instalados (32 bits)
├── Users\
│   └── NomeUsuario\
│       ├── Desktop\    → Área de Trabalho
│       ├── Documents\  → Documentos
│       ├── Downloads\  → Downloads
│       ├── Pictures\   → Imagens
│       ├── Music\      → Músicas
│       └── Videos\     → Vídeos
└── ProgramData\          → dados e configurações compartilhados entre usuários

Árvore de diretórios no Linux

/
├── bin/   → comandos essenciais (ls, cp, mv...)
├── etc/   → arquivos de configuração do sistema
├── home/
│   └── nomeusuario/  → seus arquivos pessoais — equivalente a Users\NomeUsuario no Windows
├── root/  → pasta pessoal do superusuário (root), não a raiz "/"
├── usr/   → programas, bibliotecas e a maior parte dos comandos instalados
├── var/   → dados que mudam com o tempo: logs, cache, filas de impressão
├── tmp/   → arquivos temporários, apagados a cada reinicialização
└── mnt/, /media/  → onde discos e pendrives externos são "montados"

Repare que os dois seguem a mesma lógica — uma pasta pessoal para os arquivos do usuário (Users\NomeUsuario ou /home/nomeusuario), pastas para os programas instalados e pastas reservadas para o próprio sistema. A diferença está em como essa árvore começa: no Windows, uma raiz por letra de unidade; no Linux, uma única raiz para tudo.

02 · TERMINALNavegando pelas pastas no shell+

Os comandos abaixo fazem praticamente a mesma coisa em Bash (Linux/macOS) e PowerShell (Windows) — só a sintaxe muda. Vale lembrar: no PowerShell, dir e ls são apenas dois nomes (aliases) para o mesmo comando, Get-ChildItem.

Onde você está

# Bash
pwd

# PowerShell
pwd

pwd (print working directory) mostra o caminho completo da pasta atual. Funciona nos dois shells.

Listando o conteúdo da pasta

# Bash
ls -la

# PowerShell
dir

ls lista arquivos e pastas; com -la, mostra também os ocultos e detalhes como tamanho e data. No PowerShell, dir (ou ls, é a mesma coisa) já lista tudo, incluindo ocultos.

Entrando e saindo de pastas

cd projetos
cd ..
cd

cd nome-da-pasta entra na pasta; cd .. sobe um nível. Sozinho, cd tem comportamento diferente em cada shell: no Bash leva para a pasta pessoal (home); no PowerShell, apenas mostra a pasta atual.

Criando uma pasta

mkdir nova-pasta

mkdir (make directory) funciona igual nos dois shells e cria a pasta dentro do diretório atual.

Removendo arquivos e pastas

# Bash
rm arquivo.txt
rmdir pasta-vazia
rm -r pasta-com-conteudo

# PowerShell
del arquivo.txt
rmdir pasta-vazia
rmdir -Recurse pasta-com-conteudo

rm/del remove arquivos. rmdir remove pastas, mas só quando estão vazias — em ambos os shells. Para remover uma pasta com arquivos dentro, é preciso um comando recursivo: -r no Bash, -Recurse no PowerShell. Nenhum desses comandos envia o arquivo para a lixeira: a remoção pelo terminal é direta e não tem "desfazer".

03 · WINDOWS EXPLORERManipulando arquivos e pastas com o mouse+

No Windows, o Explorador de Arquivos (Windows Explorer) faz por clique tudo o que o terminal faz por comando:

  • Criar uma pasta — clique com o botão direito em um espaço vazio → Novo → Pasta (ou o atalho Ctrl+Shift+N).
  • Renomear — selecione o arquivo ou pasta e pressione F2, ou clique com o botão direito → Renomear.
  • Copiar e mover — Ctrl+C copia, Ctrl+X recorta (move) e Ctrl+V cola no destino. Também é possível arrastar o item para outra pasta para movê-lo.
  • Excluir — a tecla Delete envia o item para a Lixeira, de onde pode ser restaurado. Shift+Delete exclui permanentemente, sem passar pela Lixeira.
  • Selecionar vários itens — Ctrl+clique seleciona itens individualmente; Shift+clique seleciona um intervalo; Ctrl+A seleciona tudo na pasta atual.
  • Mostrar arquivos e extensões ocultos — na aba Exibir do Explorador, marque Itens ocultos e Extensões de nomes de arquivos. Por padrão, o Windows esconde arquivos de sistema e a extensão de arquivos conhecidos — o que às vezes confunde quem está aprendendo a organizar um projeto.
